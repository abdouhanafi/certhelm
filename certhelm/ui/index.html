Alerting par e-mail (SMTP)
Ces réglages sont enregistrés, mais l'envoi automatique d'e-mails via ce serveur SMTP nécessite une prise en charge côté backend (module Python de dispatch). Sans cette brique côté serveur, ils restent stockés mais inactifs — à faire suivre à qui maintient le backend.

C'est l'adresse et le jeton à renseigner dans agent_config.json sur chaque serveur (voir docs/agents.md). Le PC qui héberge CertHelm doit être joignable depuis vos serveurs sur ce port.
Renouvellement automatique
En mode Réel, cliquer sur « Renouveler » passe une vraie commande chez DigiCert (potentiellement facturée), fait générer une nouvelle clé sur le serveur puis y remplace automatiquement le certificat. Commencez par Simulation : elle montre exactement ce qui serait commandé, sans rien envoyer.
Pour un premier essai réel sans risque de facturation, utilisez l'environnement de démonstration DigiCert : https://demo.digicert.com/services/v2 (avec une clé API de cet environnement). Le renouvellement n'avance que si CertHelm reste ouvert. Chaque serveur doit aussi l'autoriser dans son agent_config.json ("allow_cert_management": true).
